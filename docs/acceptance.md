# 本地验收手册与交付边界

日期：2026-09-12。目标是先验收可独立运行的本地有据购物，再单独验收真实拍照和手机交互。下面的人工步骤不是已经完成的真机测试记录。

## 0. 启动和检查数据边界

按[README](../README.md)从backend目录启动单worker服务。不要同时启动第二个进程共用会话文件。打开 `http://127.0.0.1:8000/docs`，GET `/health`应返回ok；再GET `/api/v1/knowledge/products`，应看到18条固定虚构样例及catalog.notice/sha256。没有模型密钥也应可完成以下API购物步骤。

Flutter先检查 `android-app/lib/utils/constants.dart` 的API地址是否指向当前电脑；它不是动态发现。默认后端绑定127.0.0.1，真机需绑定电脑可信局域网IP。不修改防火墙或暴露公网作为自动排错步骤。

## 1. 基础购物与证据

创建新会话（每次验收换ID）：

```json
{"message":"推荐耳机，预算500元，最好主动降噪","session_id":"acceptance-20260912-a","shopping":{}}
```

预期：HTTP200，workflow.status=ready；需求有耳机、预算hard上限、主动降噪soft；每件候选的**整个样例价格区间**不超过500；可见硬检查、软检查、分项和证据ID，而不只是聊天文案。

在Flutter聊天页输入同一句，检查节点状态、样例声明、满足／未满足／未知条件、展开证据与分数。无软偏好时0分和稳定ID排序不是错误，也不代表产品质量0分。

## 2. 多轮追问、报告与恢复

同一会话发送“解释推荐”“对比候选”“生成报告”；保留之前条件，报告choices与本轮推荐一致，带目录SHA和证据。Flutter打开／导出决策报告，不应变成旧的自由生成报告。

刷新／离开再回聊天，使用已保存session_id读回快照。GET只读，不重新执行POST；历史卡片不可冒充当前revision。报告前后包含未知参数的鞋／包也应恢复；4E已修复null被省略的会话损坏。旧已坏文件仍需新会话，不能自动补造商品参数。

## 3. 缺失、冲突与零候选

分别使用新会话：

| 输入 | 预期 |
| --- | --- |
| `推荐耳机` | 追问硬预算上限，不假设500元 |
| `推荐耳机，预算至少800元，预算不超过500元` | 冲突，无推荐，不自动倒置或放宽 |
| `推荐耳机，预算1元` | 无合格候选，说明需确认调整 |
| `推荐运动鞋，预算1000元，必须防水等级IPX8` | 不把未知防水等级当已满足，无合格候选 |

条件撤销／修改需在Flutter确认，提交当前revision。确认后才重新过滤；若收到409应先刷新当前会话，不能盲重发。**没有“必须”的文本参数默认soft**，详见[真实失败案例](evaluation.md#失败案例与下一轮方向)。

## 4. 明确长期偏好

聊天页菜单打开长期偏好：查看 → 添加带品类的条件 → 明确确认保存 → 编辑 → 选择应用到当前会话 → 删除。预期：

- 没有明确确认不能写入；仅保存用户表达，不从模型推断。
- 应用时携带偏好ID和版本，现有硬条件不会被自动覆盖。
- 不跨品类套预算；冲突需要确认。
- 删除长期偏好不自动撤销当前会话中已确认的条件。
- 重启服务后SQLite仍可读取；未启动Redis／PostgreSQL不影响默认本地模式。

接口细节见[API](api.md)；本机默认SQLite文件在backend/data/preferences.sqlite3，不应上传。

## 5. 原有页面兼容与数据真实性

- 单／多目标入口、识别结果编辑、进入聊天仍保留。
- compare只展示同一份固定样例，未知品牌／颜色不会偷偷改成全库；取消筛选须用户点击确认。
- 旧report用有效目录ID，例如sample-audio-01；无ID／未知ID返回422，不根据客户端价格生成“最优结论”。新购物报告走workflow.report。
- trend明确“未接入历史价格”，没有随机曲线或预测入手点；suggest为导航，不承诺官方渠道保障。
- 所有价格相关位置标明样例，不显示伪造评分、销量、抓取时间或实时报价。
